日期：2026-11-01。功能分支 `codex/invitation-details-20261101`，起点 `e4f22810a`（已发布应用源码 ba844d202）。只开发和隔离验证；未连接或变更生产，未推送、合并或发布。

## 交付行为

- 钱包 → 邀请奖励 → 点击邀请人数，按当前账号的直接邀请关系显示用户名，支持搜索、分页和空状态。删除账号不显示，累计邀请计数保持既有规则。
- 后台系统 → 运营 → 邀请金额可见范围：默认关闭、全部邀请方、仅指定用户。搜索用户名选择，保存稳定用户 ID，一次原子更新；空名单不授权。只有当前数据库中的启用 Root 用户可保存或搜索后台用户。
- 默认响应只有用户名，没有金额、邮箱、余额、订单号、兑换码或支付账户。邀请方只能查自己的受邀用户，客户端传 inviter_id 无效。
- 授权后按币种分别展示充值实付、订阅实付、兑换折算和合计。订阅充值镜像去重，精确十进制计算；有效实付 0 保持为 0。
- 管理员充值按现有业务单位单独标注。兑换显示折算额度基准及汇率；新快照保留历史基准、币种与自定义单位，历史缺失快照的折算标为当前估算。
- 缺失可靠历史实付或币种的记录不并入已确认合计，保留未确认金额及计数。无限额订阅兑换或无法恢复授予额度的记录显示无法折算计数。已用兑换码软删除仍计入；有快照的物理清除记录仍保留统计。
- 每次请求从数据库重新判定权限，响应前再核验；私有禁止缓存。界面切换账号、刷新及请求失败清理旧金额，打开时每 15 秒重新查询权限；关闭授权后的下一次请求立即隐藏。
- 独立报告快照不改写余额、返奖、订单金额或订阅重置锚点。快照失败不撤销已成功的入账/兑换；原记录可通过同一幂等记录函数补录。

## 边界与限制

- 真实第三方网关下单、扣款、Webhook 投递没有实际支付端到端验收；金额单位转换与已校验成功回调分支由测试和代码检查覆盖。未把夹具当作生产支付证明。
- PostgreSQL 9.6、MySQL 5.7.8 没有运行旧引擎实测；迁移/查询使用 GORM 和这些版本支持的普通连接/子查询，不使用专有 JSON/聚合函数。生产数据库体量下的迁移耗时、峰值查询压力仍需发布前测量。
- 统计现有成功支付的累计记录额，不是扣退款后的净收入。没有可靠源记录且没有快照的物理清除历史无法恢复，不伪造为 0。
- 历史未确认明细每用户最多 50 种金额组，折算基准最多 50 组，超过会明确标记；未知记录总数保持完整。金额主汇总不按记录数截断。
- 真实 fhy / 订阅 131 未参与本次测试，也未被读取或修改；只能确认测试夹具的额度和重置锚点在测试前后相同。生产该订阅的核对属于获准发布时的检查。
