## 切换及异常回滚

`release_worker.py` 持有独占锁并拒绝已有 journal 重放；只对两个生产 Caddy 上游暂时维护，配合带本次专属注释的网络规则排空现有请求，等待额度批量落库。停止原 app 后再做切换点数据库备份与全账务指纹，完整保留旧容器，切换应用。

启动后比较所有原用户/令牌、订阅、充值、兑换码、配置及渠道配置摘要，并比较 fhy 订阅 131 全行。仅允许新表/索引及来源标签、应用 VERSION 这些已知差异。只读管理接口验证默认名单、无金额字段、未登录拒绝以及既有页面。恢复原路由后观察 10 分钟，检查内外网健康、其他容器/Caddy 文件、金额默认关闭、容器重启/OOM和 fhy 零点计划。

异常切回原容器和镜像，继续使用当前生产数据库；不要用旧备份覆盖切换后的充值和消费。Caddy 遥测失效不阻止旧应用恢复；紧急恢复不依赖日志/审计文件能够写入；独立 guardian 监视 worker 心跳。正确发生的自然零点重置被允许，提前或漂移的锚点不被允许。

若需手动回滚，先核实当前候选和私有 journal，再用本次私有目录的 `release_worker.py --rollback`；运行中可向经 cmdline 核实的 worker 发送 SIGTERM，进入同一回滚路径。最终需核验旧镜像、路由、规则清理和健康。回滚未能恢复公网路由时必须明确报告，不能仅以旧 app 已启动宣称恢复完成。
